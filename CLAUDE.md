# Harmony Manual (Appunti sparsi di Armonia)

This project is a comprehensive manual on tonal harmony, blending musical theory with insights from physics (acoustics) and mathematics (modular arithmetic).

## Project Overview

The document is a LaTeX-based book titled **"Appunti sparsi di Armonia"**. It uses a custom Python engraving engine (`tools/armonia/`) to render musical examples into vector PDFs (`esempi_gen/`), included in LaTeX via the `\musica{id}` macro.

### Key Technologies

*   **LaTeX (LuaLaTeX):** The primary typesetting engine.
*   **Custom Python Engraver (`tools/armonia/`):** Based on ReportLab and FontTools for vector musical snippets (SATB grand staff, voice-leading arrows, figured bass, Roman numerals).
*   **TikZ:** Used for geometric diagrams (e.g., the Circle of Fifths).
*   **tcolorbox:** Provides stylized containers for definitions, examples, and technical notes.

## Language and Localization

*   **Language:** The project is written entirely in **Italian**. All technical terms must follow Italian musical nomenclature (e.g., "Sesta Napoletana", "Settima di Dominante").
*   **Musical Nomenclature:** Use Italian note names (Do, Re, Mi, Fa, Sol, La, Si).

## Building and Running

### Prerequisites

1.  **TeX Live:** A full TeX distribution (e.g., TeX Live 2023 or newer).
2.  **LuaLaTeX:** The document is compiled with `lualatex`.
3.  **Python 3:** With `reportlab` and `fonttools` (`pip install reportlab fonttools`).

### Generation and Compilation Commands

1.  **Generate musical examples:**
```bash
python3 tools/build_esempi.py
```

2.  **Compile the manual:**
```bash
lualatex manuale.tex
```

## Development Conventions

### Musical Symbols and Formatting

*   **Sharps and Flats in Text:** For musical alterations within the LaTeX text, **always use the commands `\sharp` and `\flat`** (often within math mode: `$\sharp$` and `$\flat$`).
    *   *Do not* use literal Unicode characters (♯, ♭) or simple characters (#, b) in the main body text.
    *   Example: `Do$\sharp$`, `Si$\flat$`.

### Musical Examples Integration

Musical examples are generated by the modules of `tools/esempi/` (voice-leading solver `tools/armonia/solver.py`, register and separation control `tools/armonia/registro.py`; hand-written data, if any, go in `tools/esempi/dati/`), and included in LaTeX via:
```latex
\begin{esempio}[Titolo esempio]
    \label{ex:mio_esempio}
    \musica{es_capXX_YY}
\end{esempio}
```

### Custom LaTeX Environments

The project uses several `tcolorbox` environments to categorize information:

*   `definizione`: Formal music theory definitions.
*   `esempio`: Musical examples.
*   `regola`: Theoretical rules.
*   `errore`: Common mistakes to avoid.
*   `fisica`: Scientific insights into acoustics.
*   `matematica`: Mathematical formalizations of musical concepts.

### Organization

*   **Modular Chapters:** Keep individual chapters in the `Capitoli/` directory.
*   **Cross-references:** Use `\label` and `\ref` extensively to link concepts across the manual.

### Registro e separazione delle voci
Negli esempi SATB le voci stanno nella zona medio-alta (`ZONA` in `tools/armonia/registro.py`: S Sol4-Sol5, A Do4-Do5, T Mi3-Mi4, B Fa2-La3) e a distanza di almeno una terza (S-A, A-T) e una quinta (T-B), non oltre ottava, ottava, dodicesima. Il solver penalizza le scelte fuori zona; `registro.ottimizza` sposta di ottava le voci di un tratto collegato quando migliora il risultato senza introdurre errori; `test_registro_e_separazione` verifica la quota di accordi fuori zona.

### Esempi generati dal solver (settime, ritardi, sesta napoletana, seste eccedenti, progressioni)

`tools/esempi/` (`genera()`, un modulo per capitolo) costruisce questi esempi con `tools/armonia/solver.py` e `chords.py` (del motore `tools/armonia/`) e li aggiunge a `tools/esempi/dati/` in `build_esempi.py`. Le note comuni tra accordi consecutivi sono rese come semiminime legate. Il test `tests/test_esempi.py` verifica parallele/estensioni e che ogni `\musica{id}` esista.

### Grandezza degli spartiti
`\musica` include ogni PDF alla stessa scala (`\scalamusica` in `music_macros.tex` = `SCALA` in `tools/armonia/render_snippet.py`): un esempio più largo del box `esempio` va a capo su più sistemi (preferibilmente alle stanghette), mai rimpicciolito. `test_tutti_gli_esempi_entrano_nel_box_alla_stessa_scala` lo verifica.

### Sigle degli accordi
Grado sopra, numerica sintetica sotto (mai due volte): negli esempi `rn` = solo grado (`V`, `II♭`, `viiø`, `i`; maiuscolo = accordo maggiore/eccedente, minuscolo = minore/diminuito, verificato da `test_sigle_maiuscolo_minuscolo`), `fig` = numerica (`[]` stato fondamentale delle triadi, `['6']`, `['6','4']`; settime `['7']`, `['6','5']`, `['4','3']`, `['2']`); nel testo `\sigla{V}{6}{5}`. La derivazione delle cifre e le sintesi sono in `Capitoli/04_rivolti_triade.tex` (`subsec:cifratura_accordi`). `test_sigla_numerica_una_sola_volta` blocca cifre attaccate al grado.

### Verifica armonica degli esempi
`tools/rivelatore-errori-armonia/.venv/bin/python -m tools.verifica_esempi [id ...]` esporta gli esempi SATB in MusicXML e li passa al rivelatore (parallele/dirette, sensibile con eccezione di Bach "da verificare", settime, salti, distanze). Fallisce sui vincoli rigidi (`RIGIDE`); `test_rivelatore_vincoli_rigidi` fa lo stesso (saltato senza `defusedxml`, quindi lanciare pytest con quel `.venv`).

Il rivelatore (`armonia/sintassi.py`) controlla anche **cadenze** (`CA-TIPO`, `CA-FINALE`), **risoluzioni** di napoletana, seste eccedenti, 6/4 cadenziale, accordo di sensibile e ritardi (`RS-*`), **progressioni** (`PR-RILEVATA`, `PR-IRREGOLARE`) e **modulazioni/tonicizzazioni** (`MO-*`). Ogni riga stampata e' `[gravita; automatica]` (certa o condizionata a una tonalita' dichiarata: rn `Do M: I`, primo `I`/`i`, o titolo "in Do Maggiore" per i nuovi controlli) oppure `[gravita; da verificare a mano]` (tonalita' stimata o lettura ambigua). Le risoluzioni `RS-*` automatiche con gravita' errore sono vincoli rigidi (`RIGIDE`). `python -m tools.verifica_esempi --testo` confronta anche i titoli degli esempi (cadenza X, progressione per Y, modulazione A -> B, modulante/non modulante, ritardo) con i rilevamenti: `[testo; automatica]` = contraddizione (fallisce `test_titoli_coerenti_con_rilevamenti`), `[testo; da verificare a mano]` = rilevamento assente o incerto (es. ritardi in accordi incompleti, sequenze reali con settime).
